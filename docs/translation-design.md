# 逐页翻译产品设计

状态：当前仅维护网页端；客户端已移除。历史客户端视觉验收记录见根目录 design-qa.md，不能代替网页端验证。

## 范围

- 本机网页端；流式 EPUB、MOBI/AZW3、FB2；简体中文。
- 当前屏触发，完整原文段落为翻译单位；不预翻整章。
- 双语：每段原文下紧接译文；仅译文：隐藏已成功翻译的原文文字。
- 图片、原有链接和脚注标记保留；不替换原文内容、不写回书籍文件。
- 译文参与分页，页数会变化；长原文段或译文可以跨页。
- 一套 OpenAI 兼容服务；自定义 URL、API Key、model。

## 代码入口与协议链路

代码入口、缓存与书签变更的关联文件见下表；端到端改动沿请求链核对，协议行为以测试为准。

| 文件 | 职责与关联 |
|---|---|
| `reader.js` | 打开书籍、保存进度、恢复模式与书签；公开就绪状态 |
| `translation.js` | 源文样式提取、排队、缓存版本、译文渲染、可见字符定位；`getDiagnostics()` 提供只读状态 |
| `translation-format.js` | 服务端／浏览器共用片段编号、完整性和结构空白校验 |
| `ui/http-bridge.js` → `server/web.js` → `server/translation.js` | 请求载荷传递、HTTP 边界、模型提示词与响应校验；新增字段需沿链核对 |
| `ui/reader-storage.js` | IndexedDB 书籍／译文缓存、localStorage 进度与模式；缓存键与稳定书签键用途不同 |
| `paginator.js`、`epubcfi.js` | 可见范围／屏内偏移、锚点恢复、原书 CFI 与译文节点过滤 |
| `tests/translation-format-tests.js`、`tests/browser/` | 格式模块回归、真实存储与刷新／切书／进程重启验收 |

自动验收入口、就绪约定和失败快照见 `docs/web-verification.md` 的“本地验收工具”。

## 阅读流程

- 顶部一个阅读模式入口：“原文 / 双语 / 仅译文”；各阅读标签页独立，默认原文。
- 选择双语或仅译文开启翻译；选择原文关闭翻译。
- 未配置：打开设置，填写 API Base URL、API Key、model；“保存并开始翻译”。
- 已配置：选定当前屏涉及的完整原文段落，逐段提供译文。
- 渐进显示：先完成的段落先在原段落位置显示，不等前面的慢段；每次插入后依次恢复阅读锚点。
- 双语时原译文紧邻；正文统一翻页或滚动。
- 翻页或目录跳转：翻译新出现且尚未完成的原文段落。
- 翻页、目录和吸附定位立即调度；连续滚动保留 160ms 合并，避免快速滚动反复启动批次。
- 重排自身不触发下一批翻译；读者停留时不递归翻译后续章节。
- 关闭翻译：停止后续请求并隐藏译文；本次结果保留供重新开启复用。
- 双语与仅译文切换：复用完成结果，不发新请求；新露出的未译段落在后续阅读动作中处理。
- 仅译文中，未译、等待和失败段落暂显示原文及对应状态；成功后再隐藏原文文字。
- 无文字、图片页不请求；图文混排只处理文字，原图保留。
- 失败段落显示简短提示和“重试”；完成段落保留；不自动循环重试。

## 模型设置

- 全局入口：首页右上角“设置”直达；阅读页“设置 → 翻译设置”。
- 未打开书也能保存、修改和清除；同一套配置用于所有书籍。保存不改变阅读标签页的阅读模式；当前已开启翻译的阅读标签页按新配置刷新。
- 首次开启双语或仅译文而未配置时，也可进入同一表单；阅读模式仍按阅读标签页选择。
- API Base URL 示例：`https://api.example.com/v1`；model 手动填写。
- 也接受完整 `/chat/completions` 地址；规范化后仍属同一服务时可保留已存 Key。
- 表单注明：当前屏涉及的完整原文段落将发送到填写的服务地址。
- URL、model、加密 API Key 在本机保存，所有阅读标签页共用。
- 已保存的 Key 只显示状态；修改时输入新值；更换服务地址须重新填写 Key。
- 支持修改、清除配置；保存失败时保留输入，显示原因与重试入口。
- 配置变更取消旧请求、清除当前阅读标签页的旧结果；跨标签页即时通知尚未实现；损坏配置可重新填写恢复。

## 必要约束

- 模式切换、插入译文、窗口重排均保持所属原文段落的位置；不以页码保持位置。
- 译文不作为待译原文；落在译文中的位置映射回所属原段。
- 仅译文中，指向隐藏原文的目录或搜索定位须映射到对应可见译文。
- 按原文段落、目标语言、模型配置复用完成结果；失败或部分结果不冒充完成。
- 快翻时复用正在执行的请求并缓存结果；旧显示流程失效，不得把读者带回旧位置。
- 译文持久保存在浏览器中，关闭标签页后仍可复用；中止接收不承诺服务端停止计费。
- 不增加整书任务、OCR、导出、术语库、样式管理器或划词翻译。

## 验收

- 首次配置可翻译；重启、新阅读标签页复用配置。
- 同一段跨屏或改变窗口大小，不产生重复译文。
- 浏览器模式把已完成译文持久化到 IndexedDB；刷新后优先使用缓存。预取窗口按当前屏段落数的两倍计算，最低 6 段、最高 12 段，只覆盖当前 section 的后续可见内容，通常不超过 12000 个源字符；单个超长段落允许独占窗口。隐藏段落跳过，不占名额。
- 当前屏已有缓存时，先排当前页待译任务，再利用空位预取；否则在首段成功后开始。最多 6 个后台任务、全局最多 8 个段落任务，留出两个名额给新出现的正文。当前页优先，复用在途预取；翻页／跳转时移除尚未发送的旧队列任务，已发送请求保留结果。预取只缓存，不提前插入正文或在停留时递归扩张；关闭翻译、清除或修改配置仍取消请求，不保存延迟结果。
- 双语与仅译文互切不调用模型；原文、双语、仅译文间切换保持段落位置。
- 仅译文中未译、失败段落保留原文；图片、脚注标记仍可用。整条目录项都是链接时，翻译完成后隐藏英文原文，页内链接不再可点（侧边栏目录仍可导航）。
- 翻译开关后目录、选区、搜索、原文 CFI 仍正确；可正常前后翻页。
- 新增译文不会递归请求、自动翻章或反复打断当前阅读。
- 长段、标题、列表、图文、脚注与纯图片页处理正确。
- 网络失败、限流、密钥错误可恢复；失败不会移除已完成译文。
- 保留 CSP；译文按不可信文本显示；密钥不下发给书籍内容。

## 译文格式保留

- 中文正文保持 24px／1.55 行高与现有紧凑段距。H1–H6 按层级使用 36／32／28／26／25／24px。
- 译文继承原段落的字重、斜体、对齐与缩进；整段文字都包在同一种 strong/em 样式中时也保留该强调。普通正文中的局部字重／斜体按计算样式划分文本片段，保留 strong/b、em/i、CSS 和嵌套粗斜体边界，也保留粗斜体段落中的局部正常文字，不把局部强调扩大到整段。
- 显式 br、连续空行、pre／pre-wrap／pre-line 的换行按源结构提取；普通 HTML 源码缩进不变成可见换行。预格式文本保留行首缩进与行尾空白。
- 有显式换行的段落逐行翻译，再以纯文本合并；空行不调用模型，段落仍只占一个并发名额，取消后不继续下一行，也不缓存半段结果。首次可能比普通段落多次请求，后续复用整段缓存。
- 普通段落沿用旧缓存键。旧版已压平的换行或缩进段落使用单独的布局版本缓存，首次阅读时局部重译，不删除旧条目或清空其他缓存。
- 行内小标题段落另用 title-v1 缓存，以 JSON 字符串保存标题和说明两段纯文本；渲染时分别创建文本节点，仅标题附加原字重／斜体。旧段落缓存保留，普通标题与正文不重译。标题与说明顺序请求，共享一个并发名额；取消后不继续说明文字，也不缓存半段结果。
- 混合局部强调使用 emphasis-v1 缓存，键包含原段落身份、规范化的片段与源样式。HTTP 桥和本地服务传递完整上下文及编号文本片段；模型一次返回 `{id,text}` 数组，可在线内调整语序，强调按源编号对应。纯换行／缩进片段固定，重复词语各有编号。仅有原先段首小标题、后面全是普通说明的情况继续复用 title-v1；普通段落与整段强调的旧缓存键不变。
- 片段协议由 translation-format.js 在服务端和浏览器共享校验：片段与全文一致、编号完整且唯一、译文非空、结构空白不变、不跨结构边界移动、不在内容片段新增换行。不完整模型格式提示重试，不降级成无格式译文，也不写入完成缓存。一个混合段落只占一次请求和一个并发名额；取消／清除后的延迟结果不写缓存。
- 书签的原段落键保持不变；新译文缓存后验证字符偏移与滚动屏内偏移恢复。旧换行段落首次重译可能改变中文措辞与字符数，旧字符偏移仅保证落在原段落，不能声明逐字对应。
- 阅读位置按整个译文段落累计字符，恢复时遍历标题和说明的文本节点。旧行内标题段落首次重译同样只保证原段落定位；新结构缓存后的刷新／重启验证精确字符与屏内偏移。
- 正文多个样式片段也按同一段落累计字符偏移，原段落键保持不变。旧纯文本缓存没有局部格式边界，首次只重译对应混合段落并保留旧条目；措辞变化时只保证同段定位，新缓存后验证精确字符／屏内偏移，包括停在强调文字内部。链接仍保留原文交互，本次不建立译文链接映射。
- 分页范围从灰底框／引用等外层容器开始时，通过当前可见的译文文本矩形恢复真实字符光标，避免遗漏中文书签。IndexedDB 延迟加载完成后，先补齐已加载文档的缓存排版并恢复书签，再计算当前页与翻译队列，避免按原文临时版式误请求相邻段落。
- 模型结果始终通过 textContent 显示；不接收模型生成的 HTML 来恢复格式。

## iPhone 与同步

`translation-request.js` 在 Mac 与 iPhone 共享提示词、分段请求和 Qwen 参数；
iPhone 原生传输只替换配置/网络层，返回值仍由 `translation-format.js` 校验。
GitHub 同步沿用缓存键，书籍还原保留文件身份；清空缓存的 generation 防止离线旧缓存复活。
跨设备传递段落 key/字符 offset，同设备继续保留 viewportOffset。
分页器解析元素边界书签时，须从 display:contents 包装内的文字取矩形；包装元素自身没有矩形。
原生安装、同步边界与真机验收见 `docs/iphone-sync.md`。
