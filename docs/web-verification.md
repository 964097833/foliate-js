## MutationObserver 异常归属

通过内置浏览器的 CDP `Runtime.exceptionThrown` 捕获原始异常，随后读取对应脚本源码，确认：

- 报错为 `MutationObserver.observe` 的目标不是 Node。
- 栈顶位于注入脚本的第 196 行；脚本末尾映射为 `browser-page-preload.js.map`。
- 脚本包含 `codex_desktop:get-browser-webmcp-policy`，栈底出现 `node:electron/js2c/sandbox_bundle`，属于 Codex 内置浏览器的预加载脚本。
- 出错调用观察 `n.documentElement`。仓库没有创建 MutationObserver 的代码。
- 内置浏览器中的阅读 iframe 还出现了 `src` 指向有效 blob、实际文档仍为 `about:blank` 的情况；同一本书在 Chrome 正常加载。

因此，原始 MutationObserver 错误不归属于网页阅读器源码，本次没有修改 Codex 安装目录或注入脚本。它在 Codex 内置浏览器中的根本修复仍需要该浏览器组件处理；网页端改用 Chrome 完成验收，未复现此异常。

## 本次修复

- ResizeObserver 回调中的排版更新推迟到下一动画帧，并合并待执行回调，修复项目自身的 `ResizeObserver loop completed with undelivered notifications`。
- 阅读视图销毁时断开观察器、取消待执行动画帧；异步回调遇到已销毁视图或尚无 body 的 iframe 时停止布局，防止空节点样式访问。
- 没有位移的程序定位不再吞掉下一次真实滚动，滚动后会更新阅读位置与书签。
- 保存并恢复分页／连续滚动偏好。
- 译文书签记录字符偏移和屏内偏移；后续内容扩展仍保留屏内偏移。
- 切换书籍时清除上一册的翻译状态，避免原文模式残留“当前页翻译完成”。
- 浏览器测试页统计断言数和失败数；只有全部成功才显示 `Browser tests passed`。

## 复验

```sh
npm test
npx eslint@9.28.0 .
python3 -m http.server 18888 --bind 127.0.0.1
```

在 Chrome 打开 `http://127.0.0.1:18888/tests/tests.html`，确认通过数并检查控制台。页面中的存储测试应运行于独立测试端口，避免替换正常阅读站点的缓存书籍。

完整阅读流程使用 `npm run test:reader` 准备本地模拟服务与临时 EPUB，再按 README 的步骤在 Chrome 中操作。它是交互验证夹具，不是自动化端到端测试命令。可用 `npm run test:reader -- 18792 18793` 更换测试端口。

本次没有验证 Safari、Firefox、移动端、真实模型响应速度或真实服务额度；模拟模型验证的是阅读、HTTP 翻译链路及缓存恢复行为。

## 本地自动验收（2026-10-18）

后续自动复验入口以 README 的 Verification 和 `package.json` 为准。
`npm run check` 依次运行严格 lint、Node 测试、Chromium 验收及故障拒绝验证。
本轮在重新执行 `npm ci` 后，使用 Node 22.23.3 完整执行成功：
22 项 Node 测试、5 项浏览器验收（含 166 项模块断言）、6 类故障拒绝验证。

浏览器验收复用 `tests/web-reader-fixture.js`，程序化启动时由系统分配两个空闲端口，
每例使用临时配置、模拟模型和独立浏览器上下文。原有浏览器模块回归也由同一入口自动运行。
测试文件由测试侧提供，正常阅读服务的静态资源允许范围没有扩大。

五项验收覆盖模块回归、原文翻页与目录、分页译文恢复、滚动译文恢复，以及关闭浏览器进程后
使用同一临时 profile 重新启动的恢复。刷新和切书比较实际可见译文、字符偏移与屏内位置，
并要求缓存恢复时模型请求数不增加。测试退出时关闭服务并删除临时配置与 profile。

本轮自动化额外发现切书后的延迟滚动回调访问已销毁视图。`paginator.js` 现在在销毁时
取消滚动防抖计时器并移除监听，定位回调也检查有效文档；浏览器模块回归覆盖原生滚动已触发、
防抖回调尚未执行时销毁视图的情况。

错误监听覆盖页面和 iframe，在用例结束前持续收集运行时异常与失败断言；测试页在模块运行结束后
仍会将延迟异常和未处理 Promise 标记为失败。故障探针分别注入失败断言、运行时异常、未处理
Promise、超时、错误阅读位置和缺失翻译缓存；必须得到非零退出码和对应错误证据才算探针通过。
位置与缓存探针实际破坏临时存储，再走正常刷新恢复路径。

本项目供个人本机使用，按用户要求移除 GitHub CI，保留上述本地检查命令。
失败截图、trace、错误记录和报告保存在本机的 `test-results/` 与 `playwright-report/`，
由 Git 忽略。本记录仅表示实际完成的本地验证；实际付费模型速度与其他浏览器仍不在本轮范围内。

## 译文格式与缓存兼容验证（2026-10-18）

本轮保持正文 24px／1.55 与段距不变，恢复 H1–H6 层级、整段粗体／斜体、对齐、显式换行、
空行与预格式缩进。补查发现 `Underconsumption:`、`Risk-taking:` 是段首加粗但与说明共段的行内小标题，现单独保留中文标题边界；其他局部词语与中文的强调／链接对应仍不在本轮范围。

`npm run check` 全部通过：22 项 Node 测试、215 项浏览器模块断言、9 项浏览器验收、
6 类故障拒绝验证。新增覆盖包括：

- 在双语与仅译文模式检查实际计算后的字号、字重、斜体、对齐和段距。
- 旧缓存译文直接获得新样式，无需重新翻译；局部强调不会误扩展到整段。
- 整本代表 EPUB 扫描 40 个分节：56 处独立标题／整段强调、2 处行内小标题，在双语和仅译文模式字重均保留；行内标题后的说明仍为正常字重。
- 行内标题单独使用版本缓存，旧条目不删。真实 IndexedDB 旧缓存迁移、标题内部／说明内部的字符偏移、超长偏移截断、含标题长段落的分页／滚动刷新与浏览器重启均覆盖；取消标题翻译后不继续说明请求。
- br、连续空行、pre 缩进保留；普通 HTML 源码换行不误变成可见换行。
- 布局不兼容的旧译文只新增版本缓存，不覆盖旧条目；普通段落仍复用旧键。
- 取消分行翻译后，不再发送后续行，也不保存不完整译文。
- 在 EPUB 中预置真实 IndexedDB 旧缓存，分页和连续滚动均验证刷新后的字符偏移、
  屏内偏移、阅读模式和布局；模型请求数保持不变，缓存条目完整保留。
- 分别关闭并重新启动浏览器进程，确认普通及带格式／换行的书籍均复用缓存并恢复译文位置。
- 旧书签的段落键仍能命中新的换行译文。旧版被压平的译文首次局部重译后，中文措辞可能变化，
  所以旧字符偏移仅能保证同段定位；不声明首次迁移前后的中文逐字位置相同。
